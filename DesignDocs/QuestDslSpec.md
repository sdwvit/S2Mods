# Quest DSL Spec

A single `.quest.mts` file describes a complete quest content package: quest prototype, quest nodes, dialog chains, dialog prototypes, global variables. The DSL compiler expands it into all required `Struct[]` outputs, grouped by cfg type.

## Motivation

Authoring S2 quest content via raw `new Struct()` calls requires:
- ~50 lines of boilerplate per quest node (SID, rawName, isRoot, QuestSID, Launchers, etc.)
- Manual launcher wiring between nodes (error-prone SID references)
- Separate transformer files for quest nodes, dialog prototypes, global variables, quest prototypes
- Cross-referencing vanilla .cfg files for SIDs, GUIDs, dialog chain names

A declarative DSL lets one file express the full intent. The compiler handles node creation, launcher wiring, SID generation, and output routing.

## Example: repeatable fetch quest

```typescript
// Mods/MoreSideQuestOptions/quests/RSQ05_C01.quest.mts

import { quest, dialog, globalVar } from "../../../src/quest-dsl/index.mts";

const active = globalVar.bool("MoreSideQuestOptions_RSQ05_C01_Active", false);

const q = quest("MoreSideQuestOptions_RSQ05_C01");

// --- Quest flow ---

q.start(({ set }) => {
  set(active, true);
});

q.cloneVanillaFlow("RSQ05_C01", {
  // Remap cross-quest Bridge refs:
  // vanilla cancelQuest node → our cancel entry point
  bridgeRemap: { RSQ05_cancelQuest: q.cancelSID },
});

q.cancel(({ set }) => {
  // Journal cleanup + End are auto-generated by cloneVanillaFlow
  set(active, false);
});

q.complete(({ set }) => {
  set(active, false);
});

// --- Dialog: hub menu for vendor ---

const hub = dialog.chain("RSQ05_Dialog_Sich_RSQ");

const hubMenu = hub.waitForReply("Hub_MoreSideQuestOptions", [
  { label: "addJob", next: "AddJob_MoreSideQuestOptions" },
  { label: "removeJob", next: "RemoveJob_MoreSideQuestOptions" },
  { label: "leave", terminate: true },
]);

hub.waitForReply("AddJob_MoreSideQuestOptions",
  vendors.RSQ05.subQuests.map((sq) => ({
    next: questDataTable[sq].dialogSID,
    showWhen: globalVar.ref(sq).eq(false),
  })).concat({ terminate: true }),
);

hub.waitForReply("RemoveJob_MoreSideQuestOptions",
  vendors.RSQ05.subQuests.map((sq) => ({
    next: dialog.cancelConfirm(sq),
    showWhen: globalVar.ref(sq).eq(true),
  })).concat({ terminate: true }),
);

// Per-sub-quest cancel confirm (player says "yes cancel this quest")
for (const sq of vendors.RSQ05.subQuests) {
  hub.phrase(dialog.cancelConfirmSID(sq), {
    member: -1,
    options: [{ terminate: true }],
  });
}

// Patch vanilla If nodes to redirect to hub
hub.patchOption("RSQ05_Dialog_Sich_RSQ_If", "True", { next: hubMenu.sid });
hub.patchOption("RSQ05_Dialog_Sich_RSQ_If", "False", { clear: true });
hub.patchOption("RSQ05_Dialog_Sich_RSQ_If_1", "True", { next: hubMenu.sid });
hub.patchOption("RSQ05_Dialog_Sich_RSQ_If_1", "False", { clear: true });

// --- Parent quest: SetDialog + activation chains ---

q.parentQuest("RSQ05", ({ setDialog, onConfirm, onCancelConfirm, disable }) => {
  disable("RSQ05_Random");           // strip launchers
  disable("RSQ05_SetDialog_SichRSQ"); // strip launchers

  // New SetDialog that replaces vanilla, fires from quest Start
  const sd = setDialog({
    chain: "RSQ05_Dialog_Sich_RSQ",
    npc: "7FE2532443129907B6BA259BEC0306A4",
    launchFrom: "RSQ05_Start",
    confirmPhrases: extractConfirmPhrases("RSQ05"), // from vanilla Pin_0 conditions
    cancelPhrases: vendors.RSQ05.subQuests.map((sq) => dialog.cancelConfirmSID(sq)),
  });

  // Per sub-quest: confirm → start quest + set active
  for (const sq of vendors.RSQ05.subQuests) {
    onConfirm(sd, sq, ({ consoleCommand, set }) => {
      consoleCommand(`XStartQuestNodeBySID MoreSideQuestOptions_${sq}_Start`);
      set(globalVar.ref(sq), true);
    });
    onCancelConfirm(sd, sq, ({ consoleCommand, set }) => {
      consoleCommand(`XStartQuestNodeBySID MoreSideQuestOptions_${sq}_Cancel`);
      set(globalVar.ref(sq), false);
    });
  }
});

export default q;
```

## Compiler output

`q.compile()` returns a map keyed by cfg type:

```typescript
{
  QuestPrototypes: Struct[],          // 1 entry: MoreSideQuestOptions_RSQ05_C01
  QuestNodePrototypes: Struct[],      // Start, cloned vanilla nodes, Cancel, End, parent quest nodes
  DialogPrototypes: Struct[],         // Hub menu, AddJob, RemoveJob, cancel confirms, If patches
  GlobalVariablePrototypes: Struct[], // MoreSideQuestOptions_RSQ05_C01_Active
}
```

Each struct has `__internal__.isRoot = true`, `rawName`, correct `QuestSID`. The transformer just returns them.

## DSL primitives

### `quest(sid)`
Creates a quest builder. Auto-generates QuestPrototype entry.

- `.start(fn)` — nodes that fire when quest starts (Technical entry point, triggered by XStartQuestNodeBySID)
- `.cancel(fn)` — nodes that fire on cancel (Technical entry point + End with ExcludeAllNodesInContainer)
- `.complete(fn)` — nodes that fire when the quest completes naturally (inserted before End)
- `.cloneVanillaFlow(vanillaSID, opts)` — reads vanilla .cfg, clones all nodes with remapped SIDs; auto-generates journal cancel nodes for `.cancel()`; `opts.bridgeRemap` redirects cross-quest Bridge conditions
- `.parentQuest(questSID, fn)` — generates nodes in the parent quest file (SetDialog, ConsoleCommand chains, disable nodes)
- `.cancelSID` — the SID of the cancel Technical node (for bridgeRemap)
- `.compile()` — produces final Struct[] grouped by cfg type

### `dialog.chain(chainSID)`
Creates a dialog chain builder. All generated dialog prototypes get `DialogChainPrototypeSID = chainSID`.

- `.waitForReply(sid, options[])` — WaitForReply node with conditional options
- `.phrase(sid, opts)` — dialog phrase (getDialogPhrase wrapper)
- `.patchOption(existingSID, branch, patch)` — bpatch an existing dialog's NextDialogOptions branch

### `globalVar.bool(sid, default)`
Declares a GlobalVariablePrototype. Returns a ref object with `.eq(value)` for dialog conditions and `.set(value)` for quest node actions.

### Phase builder (the `fn` argument)
Each phase callback receives a builder with:
- `set(varRef, value)` — SetGlobalVariable node
- `journal.start(quest, stage?, opts?)` / `.finish()` / `.cancel()` / `.cancelAll()`
- `consoleCommand(cmd)` — ConsoleCommand node
- `reward(generatorSID)` — SetItemGenerator node

Nodes within a phase fire in parallel from the phase's entry point (same as S2's launcher model). Sequential ordering requires explicit chaining: `after(node, fn)`.

## Integration with existing transformer system

The `.quest.mts` files are NOT standalone scripts. They're imported by a thin transformer:

```typescript
// Mods/MoreSideQuestOptions/transformQuestNodePrototypes.mts
import rsq05c01 from "./quests/RSQ05_C01.quest.mts";
// ... all other quests

export function transformQuestNodePrototypes(struct, context) {
  // compile all quests, return structs matching the current file
  const allQuests = [rsq05c01, ...];
  return allQuests.flatMap(q => q.compile().QuestNodePrototypes);
}
transformQuestNodePrototypes.files = [...parentQuestFiles];
```

Or a single `quest-loader` transformer that auto-discovers `.quest.mts` files in the mod directory.

## What this does NOT cover (future work)

- **Spawns/items**: `cloneVanillaFlow` copies them verbatim from vanilla; authoring new spawns from scratch needs spawn actor / item prototype integration
- **Localization**: dialog text is referenced by existing label SIDs; new text needs TextDatabase entries (separate system)
- **Visual editor**: the DSL is text-only; a visual node graph that emits DSL code could come later
- **Validation**: runtime checks (e.g. "this SID doesn't exist in vanilla") could be added to `.compile()`

## Relationship to existing `src/quest/` pipeline

The existing `src/quest/` code goes `.cfg → IR → JS` (for visualization/debugging). The DSL goes `TypeScript → Struct[] → .cfg`. They're complementary:
- `src/quest/ir.mts` defines `QuestIrNode` which informed the DSL's internal node model
- `src/quest/normalize.mts` shows how launcher graphs are traversed (same pattern used in `cloneVanillaFlow`)
- The DSL could optionally output IR for feeding into the existing JS codegen (quest visualization)
