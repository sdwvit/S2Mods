## Introduction

In this guide, we'll look at placeholder patching, deletion, and addition.

> **WARNING**
> This guide focuses on the specifics of modding placeholder actors, skipping most descriptions and details of the shared mechanisms covered in the prerequisite docs.

## Design & work principles

The main point to understand is that, specifically in Zone Kit, any modifications to placeholders work alongside the other basic actor modification systems. However, in PIE sessions or while in-game, the changes are driven purely by `.cfg` files. This means that, for example, placeholder patching is more limited and has more restrictions than actor patching.

> **WARNING**
> Please refer to the [Known issues & limitations](#known-issues--limitations) section at the end of the guide for more details.

While different types of Spawn Actor Prototypes have different properties, the following ones are worth going through separately:

1. **`SpawnOnStart`** – indicates whether the actor will be automatically spawned at the start of the game (either by loading into an existing campaign or starting a new one) or by a specific script or event.
   1. Examples of the former type are mostly preplaced items, containers with loot, NPCs, and mutants in the open world.
   2. Examples of the latter type are mostly quest-related entities, which need to be spawned manually based on specific conditions, e.g., after starting a quest.
2. **`SpawnType`** – the actual type of the Spawn Actor Prototype.
3. **`NodePrototypeAppliedMods`** – not present in vanilla placeholders. Explored more in the section below.

> **NOTE**
> As with regular `.cfg` mods, you can tweak the generated Spawn Actor Prototype file yourself (or even create one manually).

In Zone Kit, Spawn Actor Prototype `.cfg` files are generated at the following locations:

| Use case | Definition | Zone Kit path example |
|---|---|---|
| Modded placeholder | `Stalker2\Mods\<ModName>\Content\GameLite\GameData\SpawnActorPrototypes\...` | `Stalker2\Mods\MyPlaceholderDeletion\Content\GameLite\GameData\SpawnActorPrototypes\WorldMap_WP\9A41EE1649839E16066221BAE266390E.cfg` |
| New placeholder | `Stalker2\Mods\<ModName>\Content\GameLite\ModGameData\SpawnActorPrototypes\...` | `Stalker2\Mods\MyNewPlaceholder\Content\GameLite\ModGameData\SpawnActorPrototypes\WorldMap_WP\9A41EE1649839E16066221BAE266390E.cfg` |

It's also important to understand the basics of how placeholder (or, more properly, Spawn Actor Prototype) modifications are actually applied under the hood. Here's an overview of the algorithm, which is run during gameplay:

1. If the corresponding prototype has already been spawned and it has been changed (modded, the version is different, etc.), delete it to prevent duplicates.
2. If it's a `SpawnOnStart` prototype, spawn a new actor from the modified Spawn Actor Prototype.
3. If it's not a `SpawnOnStart` prototype, spawn it regularly when needed.

This means that already created actors do not get directly overwritten by mods, but instead the older version is deleted and a new one is recreated using the modded prototype `.cfg` file.

> **NOTE**
> The steps in the algorithm are true for any placeholder modifications – addition, deletion, or patching.

## Patching vanilla placeholders

The actor patching system generates not only regular patches when patching placeholders, which are saved to the corresponding Mod Actor Patches Data Asset file, but it also automatically creates a `.cfg` file based on the modified placeholder:

*(Screenshot of the editor log, transcribed:)*

```
LogModKitPlaceholderManager: Saved modded placeholder config node:
    Placeholder SID - 9A41EE1649839E16066221BAE266390E
    Config path - ../../Mods/MyActorDeletion/Content/GameLite/GameData/SpawnActorPrototypes/WorldMap_WP/9A41EE1649839E16066221BAE266390E.cfg
```

## Deleting vanilla placeholders

The actor deletion system generates not only regular deletion infos when deleting placeholders, which are saved to the corresponding Mod Actor Deletions Data Asset file, but it also automatically creates a `.cfg` file based on the modified placeholder:

*(Screenshot of the editor log, transcribed:)*

```
LogModKitPlaceholderManager: Saved placeholder deletion patch:
    Placeholder SID - 9A41EE1649839E16066221BAE266390E
    Config path - ../../Mods/MyActorDeletion/Content/GameLite/GameData/SpawnActorPrototypes/WorldMap_WP/9A41EE1649839E16066221BAE266390E.cfg
```

Here's an example of a deleted placeholder prototype `.cfg` file:

```
// BP_ItemPlaceholder_C_UAID_00D861D9738DF7D901_1884212591
9A41EE1649839E16066221BAE266390E : removenode
```
